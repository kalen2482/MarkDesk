严重 Bug (Critical)

#01 双向同步时序错误：预览编辑后内容被覆盖 严重 已修复
文件
src/components/Preview.tsx
问题描述

Preview 组件使用 lastSyncSource ref 跟踪同步来源，但该 ref 在独立的 useEffect 中更新，该 effect 在 content effect 之后执行。当用户在预览区编辑时，syncSource 和 content 在同一次渲染中同时变化，但 content effect 先执行，此时 lastSyncSource.current 仍然是旧值（非 'preview'），导致预览区重新渲染——将用户的富文本编辑替换为 markdown 往返转换的结果，造成光标跳动和内容丢失。

修复方案

移除 lastSyncSource ref 及其独立 useEffect，改为在 content useEffect 的依赖数组中直接包含 syncSource prop，在 effect 内部直接检查 syncSource === 'preview'。这样在同一次渲染中，content effect 能看到最新的 syncSource 值。

#02 撤销/重做在可视化模式下不更新预览 严重 已修复
文件
src/App.tsx — handleUndo / handleRedo
问题描述

当用户在预览区编辑后执行撤销/重做，handleUndo/handleRedo 更新了 content 但没有设置 syncSource。此时 Preview 的 syncSource prop 仍为 'preview'（来自上一次预览编辑），content effect 检测到 syncSource === 'preview' 后跳过了渲染，导致撤销/重做操作在预览区无效果。

修复方案

在 handleUndo 和 handleRedo 中，更新 content 之前设置 syncSourceRef.current = 'editor' 和 setSyncSource('editor')，确保 Preview 知道这次内容变更来自编辑器侧（而非预览编辑），从而正常重新渲染。

#03 切换标签页清除撤销/重做历史 严重 已修复
文件
src/App.tsx — handleTabClick / handleTabClose
问题描述

handleTabClick 每次点击标签时都执行 historyMapRef.current.set(tab.id, { stack: [tab.content], index: 0 })，将历史栈重置为单条记录。这意味着用户在标签 A 做了 50 步编辑，切换到 B 再切回 A，所有撤销历史全部丢失。handleTabClose 也有同样问题——关闭标签时对新的活动标签重置历史。

修复方案

handleTabClick 移除历史重置，仅调用 updateHistoryFlags()。getHistory 本身已有惰性初始化逻辑（找不到历史时自动创建），无需手动设置。handleTabClose 改为仅在历史不存在时才初始化。

#04 自动保存永远不会触发 严重 已修复
文件
src/App.tsx — auto-save useEffect
问题描述

自动保存的 useEffect 依赖数组包含 tabs，而 tabs 在每次按键时都会变化。每次 content 变化都会清除旧 interval 并创建新 interval，但新 interval 的等待时间（默认30秒）永远不会到期——因为用户在30秒内一定会再按键，interval 又被重建。结果：自动保存功能形同虚设。

修复方案

从依赖数组移除 tabs，引入 tabsRef（const tabsRef = useRef(tabs); tabsRef.current = tabs），interval 回调中读取 tabsRef.current 获取最新 tabs。这样 interval 只在设置变化时重建，定时器能正常到期。同时修复 beforeunload handler 也使用 tabsRef 并从依赖数组移除 tabs。

#05 下划线语法 __text__ 与 GFM 加粗冲突 严重 已修复
文件
src/App.tsx (underline action), src/utils/editorActions.ts, src/utils/markdown.ts
问题描述

源码模式下划线操作插入 __text__，但在 GFM 规范中 __ 是加粗（<strong>）语法。marked 解析器会将 __下划线文本__ 渲染为 <strong>下划线文本</strong>，而非下划线。markdown.ts 的渲染管线也没有对 __ 做下划线预处理，导致功能完全失效。

修复方案

源码模式改为插入 <u>text</u> HTML 标签（Obsidian 兼容）。markdown.ts 新增预处理步骤：在 marked 解析前用正则提取 <u>...</u>，替换为占位符，解析后恢复。htmlToMarkdown.ts 已有 Turndown 规则将 <u> 转回 <u>text</u>，保持一致。

#06 DOMPurify 禁止 input 标签导致任务列表复选框被移除 严重 已修复
文件
src/utils/markdown.ts — DOMPurify.sanitize 配置
问题描述

DOMPurify 配置中 FORBID_TAGS: ['script', 'iframe', 'form', 'input', ...] 禁止了 input 标签。但 marked 的 GFM 任务列表渲染会生成 <input type="checkbox" disabled>，被 DOMPurify 直接移除，导致任务列表的复选框不显示。

修复方案

从 FORBID_TAGS 中移除 'input'。DOMPurify 默认允许 input 标签，且 FORBID_ATTR 已禁止 onfocus、onchange 等事件属性，安全性不受影响。

中等 Bug (Medium)

#07 可视化模式下侧边栏大纲导航失效 中等 已修复
文件
src/App.tsx — handleHeadingClick
问题描述

handleHeadingClick 通过 textareaRef.current 操作 textarea 进行光标定位和滚动。在可视化模式下 textarea 不渲染，textareaRef.current 为 null，函数直接 return，侧边栏点击标题无任何反应。

修复方案

当 textarea 不存在时，改为在预览容器中查找对应的 heading DOM 元素（通过文本匹配），调用 el.scrollIntoView({ behavior: 'smooth', block: 'start' }) 滚动到该标题。

#08 可视化模式下右键菜单剪贴板操作失效 中等 已修复
文件
src/App.tsx — contextMenuItems
问题描述

右键菜单的剪切/复制/粘贴项直接操作 textareaRef.current，在可视化模式下 textarea 不存在，操作直接 return。虽然加粗/斜体等项通过 applyAction 已支持可视化模式（走 dispatchRtAction），但剪贴板操作被遗漏。

修复方案

在每个剪贴板操作前检查 isPreviewFocused()，若是则使用 document.execCommand('cut'/'copy') 和 document.execCommand('insertText', false, text) 操作 contenteditable，否则走原有 textarea 逻辑。

#09 可视化模式下搜索替换失效 中等 已修复
文件
src/App.tsx — handleSearchNavigate / handleSearchReplace / handleSearchReplaceAll
问题描述

三个搜索函数都依赖 textareaRef.current 进行光标定位和文本替换。可视化模式下 textarea 不存在，搜索面板可以显示匹配结果但无法导航到匹配位置或执行替换。

修复方案

handleSearchNavigate：textarea 不存在时按 content 比例滚动预览容器。handleSearchReplace：直接在 content 字符串上执行替换，设置 syncSource='editor' 触发预览更新。handleSearchReplaceAll：同样直接操作 content 字符串。

#10 可视化模式下图片粘贴失效 中等 已修复
文件
src/App.tsx — handlePasteImage
问题描述

handlePasteImage 开头 if (!ta) return，可视化模式下 textarea 不存在时直接返回，粘贴图片无任何效果。注意：此函数仅在 Editor 组件的 onPasteImage 回调中使用，而 Editor 在可视化模式下不渲染，所以粘贴图片事件根本不会触发——但修复后即使从其他途径调用也能正常工作。

修复方案

textarea 不存在时，将图片 markdown 追加到 content 末尾，设置 syncSource='editor' 触发预览渲染。

#11 删除线快捷键提示错误 中等 已修复
文件
src/components/Toolbar.tsx
问题描述

工具栏删除线按钮的 Tooltip 显示快捷键为 Ctrl+Shift+S，但该快捷键实际绑定的是"另存为"（handleSaveAs）。用户按 Ctrl+Shift+S 期望加删除线，实际触发了另存为对话框。

#12 Mermaid 图表不适配暗色模式 轻微 已修复
文件
src/components/Preview.tsx
问题描述

Mermaid 初始化时 theme 硬编码为 'default'（浅色），切换到暗色模式后图表背景仍然为白色，与深色背景不协调。且初始化只执行一次，切换主题后不会重新渲染。

修复方案

初始化时读取 document.documentElement.classList.contains('dark') 设置 theme。添加 MutationObserver 监听 <html> 的 class 变化，主题切换时重新初始化 Mermaid 并清除已渲染的 SVG 触发重渲染。

#13 已移除的 'preview' 模式仍存在于类型和渲染逻辑中 轻微 已修复
文件
src/types.ts, src/App.tsx
问题描述

DisplayMode 类型仍包含 'preview'，UI 工具栏已移除预览按钮但渲染逻辑仍检查 displayMode === 'preview'。如果 localStorage 中的 defaultDisplayMode 为 'preview'，应用会进入只读预览模式且无 UI 按钮可切换（虽然 Ctrl+E/Ctrl+R 快捷键仍可用）。

修复方案

在 displayMode 的 useState 初始化中添加规范化：return s.defaultDisplayMode === 'preview' ? 'visual' : s.defaultDisplayMode，将遗留的 'preview' 设置自动转换为 'visual'。
